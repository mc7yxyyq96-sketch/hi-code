# Industrial Control Box Demo

This sample proves the Hi Code industrial workflow can create a complete, auditable project package from requirements through release evidence.

## Goal

`Industrial Control Box Demo` models a small industrial control box with software, CAD, PCB, PLC, electrical, BOM, documentation, quality gates, and a release package. It is generated by the real sample project service and persisted in the current workspace.

## Entry Points

- Renderer: Industrial Project -> Sample Project -> `Create Sample Industrial Project`
- IPC: `sample:industrial-control-box:create`
- Core: `createIndustrialControlBoxSample({ workspacePath, overwrite, runInstalledTools })`

By default `runInstalledTools` is false, so external tools are not executed. If the user explicitly enables it, installed local tools may be called through the existing adapter permission path.

## Domain Packs

The creator enables the packs used by this sample:

- `mechanical-cad`
- `pcb-eda`
- `plc-automation`
- `energy-electrical` for the requested electrical domain
- `manufacturing-qa`
- `software-product` for the requested documentation domain

The alias mapping is stored in project metadata so future readers can see that `electrical` maps to `energy-electrical` and `documentation` maps to `software-product`.

## Tool Installation And Dry Run

FreeCAD:

- If `FreeCADCmd` or `freecadcmd` is installed and the user explicitly enables tool execution, the FreeCAD adapter attempts real enclosure generation.
- If not installed or not approved, Hi Code writes `freecad-run-plan.md`, `expected-input.json`, `expected-artifacts.json`, and `metadata.json` with `simulated: true`.

KiCad:

- If `kicad-cli` is installed and a real KiCad project exists, the adapter can run ERC/DRC/export commands.
- The sample does not create fake `.kicad_pro`, schematic, layout, Gerber, or DRC reports. Without a real project, it writes a dry-run plan and marks it simulated.

PLC / OpenPLC:

- Hi Code always generates real engineering draft files: `plc-program.st`, `io-map.csv`, `safety-interlocks.md`, FAT checklist, SAT checklist, and metadata.
- If OpenPLC/MATIEC is not installed or not approved, compile status is `not_run`. The PLC package requires human safety approval before simulation, FAT/SAT, device download, or field use.

## Quality Gates

The sample records evidence for:

- requirements completeness
- CAD artifact gate
- PCB artifact gate
- PLC safety gate
- PLC compile status gate
- BOM completeness gate
- documentation gate
- release readiness gate

`failed` and `requires_approval` gates block release. `simulated`, `not_run`, and `warning` gates do not pretend to pass; they are recorded as visible release risks.

## Real vs Simulated Artifact Rules

Real generated artifacts:

- requirements documents
- software monitor scaffold
- PLC Structured Text draft
- PLC I/O map
- PLC safety interlocks
- FAT/SAT checklists
- wiring diagram draft
- terminal list
- power budget
- system BOM
- project documentation
- gate evidence JSON
- release package files

Simulated or external-required when tools are missing or not approved:

- FreeCAD CAD model outputs
- KiCad ERC/DRC/Gerber/drill exports
- PLC compile result when OpenPLC/MATIEC is unavailable

The release notes include a `SIMULATED / DRY-RUN EVIDENCE` section so customer-facing delivery cannot hide these boundaries.
