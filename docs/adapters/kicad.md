# KiCad Adapter

Sprint 6C implements the first real PCB tool adapter for Hi Code. It supports KiCad detection, safe dry-run planning, and a real `kicad-cli` execution path for ERC, DRC, Gerber export, drill export, and BOM export attempts when the local environment supports them.

The adapter does not pretend KiCad is installed. Missing installations return `installed: false` and can only produce simulated dry-run artifacts.

## Detection

Detection checks:

- `kicad-cli` on `PATH`
- common macOS, Homebrew, Linux, and Windows install paths
- manual executable path supplied by the user
- `KICAD_CLI_PATH`
- version output from `kicad-cli --version` or the detected executable

Manual configuration example:

```json
{
  "executablePath": "/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli"
}
```

## Capabilities

The KiCad adapter declares:

- `project_inspection`
- `schematic_check`
- `pcb_drc`
- `gerber_export`
- `drill_export`
- `bom_export_plan`

## Input Schema

Tool runs accept `pcbRequest`:

```json
{
  "projectPath": "hardware/controller/controller.kicad_pro",
  "schematicPath": "hardware/controller/controller.kicad_sch",
  "boardPath": "hardware/controller/controller.kicad_pcb",
  "outputDir": ".hicode/artifacts/kicad/controller-release",
  "exportGerber": true,
  "exportDrill": true,
  "runErc": true,
  "runDrc": true,
  "bomFormat": "csv"
}
```

All paths must resolve inside the workspace. `outputDir` must be under `.hicode/artifacts`.

## Real Execution

Real execution requires:

- KiCad installed and detected
- explicit user approval
- no adapter network access
- `.kicad_pro` present
- schematic present when ERC or BOM export is requested
- board present when DRC, Gerber, or drill export is requested

The command flow is built from the request:

```bash
kicad-cli sch erc --format json --output erc-report.json <schematic.kicad_sch>
kicad-cli pcb drc --format json --output drc-report.json <board.kicad_pcb>
kicad-cli pcb export gerbers --output gerber <board.kicad_pcb>
kicad-cli pcb export drill --output drill <board.kicad_pcb>
kicad-cli sch export bom --output bom.csv <schematic.kicad_sch>
```

The adapter records `stdout` and `stderr` in `kicad-cli.log` and writes `metadata.json` for traceability.

## Dry-Run Behavior

When KiCad is missing, or when the user chooses dry-run, the adapter writes:

```text
kicad-run-plan.md
expected-input.json
expected-artifacts.json
command-preview.sh
```

These files are marked `simulated: true`. No `kicad-cli` process is started, and no Gerber, drill, ERC/DRC, or BOM output is claimed to exist.

Dry-run quality gates use simulated status and must not be treated as passed manufacturing evidence.

## Output Artifacts

Real runs can produce:

- `metadata.json`
- `kicad-input.json`
- `kicad-cli.log`
- `erc-report.json`
- `drc-report.json`
- `gerber/*`
- `drill/*`
- `bom.csv`, `bom.xml`, or `bom.json`

Every artifact is written under the requested `.hicode/artifacts/kicad/*` directory and is attached to the Job Center record.

## UI Flow

1. Open the Toolchain panel.
2. Select `KiCad`.
3. Optionally enter the `kicad-cli` executable path.
4. Enter a KiCad project, schematic, and board path.
5. Click `Run dry-run` to generate a plan and command preview.
6. Click `Run ERC/DRC/Gerber` only when KiCad is installed and the user approves local execution.

If KiCad is not installed, real execution returns a not-installed error and dry-run remains available.

## Quality Gates

The adapter checks:

- `.kicad_pro` exists
- schematic and board paths are legal and present for requested operations
- ERC/DRC command exit codes
- Gerber and drill directories contain files when requested
- BOM exists when generated by the local KiCad CLI
- metadata is written for every real run attempt

ERC/DRC failures produce failed gate results. Dry-run gates are simulated/skipped in Job Center and are not release evidence.
